## 三、快速部署（推荐）

> [!CAUTION]
>
> ### 部署铁律（所有人/AI 助手必须遵守）
>
> **本地构建 → 上传部署**时，必须完成以下 3 件事，否则 static 文件 100% 会 404：
>
> 1. **打包必须包含 3 个目录**：`.next/standalone` + `.next/static` + `public`
> 2. **解压后必须执行路径替换**：
>    ```bash
>    sed -i 's|/Users/wangpeng/Downloads/limsnext|/root/lims-next|g' server.js
>    sed -i 's|/Users/wangpeng/Downloads/limsnext|/root/lims-next|g' .next/required-server-files.json
>    ```
> 3. **static 必须放到 `.next/static/`**（不是项目根目录的 `static/`）
>
> **原理**：Next.js 构建时把本地路径（`/Users/wangpeng/Downloads/limsnext`）硬编码到 `server.js` 的 `outputFileTracingRoot` 字段。
> 部署到 Linux 后路径变为 `/root/lims-next`，如果不替换，Next.js 找不到 static 文件 → 404。
>
> **`./deploy-fast.sh` 已内置以上所有步骤，直接执行即可。**
> **禁止手动分步部署（如 scp + tar），除非严格按照上述 3 条规则操作。**

### 方式一：本地构建 + 上传（最快）

在本地机器执行，利用本地 CPU 构建，只上传压缩包：

```bash
# 1. 进入项目目录
cd /Users/wangpeng/Downloads/limsnext

# 2. 执行快速部署脚本
./deploy-fast.sh
```

**脚本执行流程**：

1. 拉取最新代码
2. 检查 `package.json` 变更，按需安装依赖
3. 同步数据库 Schema（`prisma db push`）+ 生成 Prisma Client
4. 构建项目（`npm run build`）
5. 执行种子脚本（审批流等配置数据同步）
6. 复制 static/public 到 standalone + 重启 PM2

**预计耗时**：3-5 分钟

## 七、常见部署问题及解决方案

### 🔴 7.1 Static 文件 404（ChunkLoadError）— 最常见问题

**问题现象**：

- 浏览器控制台大量 404：`GET /_next/static/chunks/xxx.js 404 (Not Found)`
- 页面白屏或报错 `ChunkLoadError: Loading chunk failed`

**根本原因（已定位）**：

Next.js **在构建时**会把本地构建路径硬编码到 `server.js` 和 `.next/required-server-files.json` 中的 `outputFileTracingRoot` 字段。例如本地路径是 `/Users/wangpeng/Downloads/limsnext`，但服务器路径是 `/root/lims-next`，路径不匹配导致 Next.js server 无法找到 static 文件。

**同时还需要确保**：

1. `.next/static/` 目录已正确放置到服务器（standalone 输出不包含此目录）
2. `public/` 目录已正确放置

**一键修复命令**：

```bash
# 在服务器上执行（修复路径 + 重启）
sshpass -p 'xxx198910170014Z' ssh root@8.130.182.148 "
  cd /root/lims-next && \
  sed -i 's|/Users/wangpeng/Downloads/limsnext|/root/lims-next|g' server.js && \
  sed -i 's|/Users/wangpeng/Downloads/limsnext|/root/lims-next|g' .next/required-server-files.json && \
  pm2 restart lims-next && \
  sleep 3 && \
  curl -s -o /dev/null -w 'Static文件测试: HTTP %{http_code}\n' http://localhost:3001/_next/static/\$(cat .next/BUILD_ID)/_buildManifest.js
"
# 期望输出: Static文件测试: HTTP 200
```

**预防措施（已内置到 deploy-fast.sh）**：
`deploy-fast.sh` 在步骤4中会自动执行 `sed` 替换路径，无需手动处理。

> **为什么之前的 word 项目没有这个问题？**
> 因为 word 项目是在服务器上直接构建的（`git pull && npm run build`），构建路径和运行路径一致。
> 而 LIMS 项目采用**本地构建→上传部署**模式，构建路径（Mac）和运行路径（Linux）不同，导致路径不匹配。

### 7.2 Prisma 跨平台问题

**问题**：报错 `Prisma Client could not locate the Query Engine for runtime "rhel-openssl-1.1.x"`

**解决**：在 `prisma/schema.prisma` 中添加：

```prisma
generator client {
  provider      = "prisma-client-js"
  binaryTargets = ["native", "rhel-openssl-1.1.x"]
}
```

### 7.3 NEXTAUTH_URL 配置错误

**问题**：登录按钮点击无反应

**解决**：确保 `.env` 中配置正确：`NEXTAUTH_URL="http://8.130.182.148:3001"`

### 7.4 端口配置

**问题**：standalone 模式默认使用 3000 端口

**解决**：使用 `PORT` 环境变量：

```bash
# ❌ 错误方式
pm2 start server.js --name lims-next -- -p 3001

# ✅ 正确方式
PORT=3001 pm2 start server.js --name lims-next --update-env
```

### 7.5 PM2 进程僵死

**问题**：`pm2 status` 显示 online 但 PID 为 N/A，服务无法访问

**解决**：

```bash
pm2 delete lims-next
pkill -f 'node server.js'
cd /root/lims-next
PORT=3001 pm2 start server.js --name lims-next --update-env
pm2 save
```

### 7.6 数据库 Schema 不同步

**问题**：API 返回 500 错误，日志显示数据库字段不存在

**解决**：

```bash
sshpass -p 'xxx198910170014Z' ssh root@8.130.182.148 "cd /root/lims-next && npx prisma db push && pm2 restart lims-next"
```
